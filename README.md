# DSH 视觉路由

轻量 Host + 设置页面插件，不实现新的供应商适配层，不储存 API key，不修改原模型的多模态能力声明。

## 安装与配置

DSH 插件 → 添加插件 → 选择此目录。适配并核对的版本：**0.2.2-rc.3**。

打开 **设置 → 视觉路由**（插件详情也提供配置）：

1. 在「非多模态模型」点击 **＋ 添加**，模糊搜索模型名称 / 模型 ID / 提供商（支持无连字符缩写，如 `gpt41` 匹配 `gpt-4.1`），点选或回车加入白名单；面板保持打开便于连续添加，× 或 Esc 关闭（Esc 先清空搜索词，再按一次才关闭）。
2. 在「视觉兜底模型」同样添加多模态模型（两个面板互斥），列表内用 ↑ / ↓ 调整兜底顺序，× 移除。
3. 按需调整单模型超时（默认 60 秒）与输出上限（默认 4096 token），失焦或回车时写入。

所有更改**实时生效**：添加、删除、排序即刻写入，无保存或确认按钮；写入失败会在顶部提示，可重试或放弃修改，编辑内容不会丢失。

默认两个列表都为空，不向任何模型注入工具，也不会发送图片请求。模型按 provider/model **区分大小写精确匹配**，页面从选项自动记录真实路由与模型 ID，无需手填。

模型目录直接读取 DSH 已注册的 LLM 提供商及其模型，不受 `dsh-scoped-models` 对原生选择器的范围筛选影响，也不依赖该插件安装。Codex 多账户保留各自实际供应商路由，不合并成无法调用的别名。能力标签仅供参考，不会强制隐藏未知视觉能力的模型。

添加面板按需弹出，不常驻整页模型目录；它展示尽可能多的候选（目录不做截断），已在该列表中的模型自动排除。目录加载失败或部分提供商不可用时在面板内提示并可重试，不覆盖已添加项及兜底顺序；新增连接后重新打开添加面板即可搜索到。视觉列表不会创建连接或自动开通模型。

## 工具

仅白名单匹配的模型步骤可以看到并执行 `vision_read`。这些步骤同时隐藏并禁止 `read_image`，并添加「当前模型无法直接识别图片，请直接使用 `vision_read`，无需先加载图片」的系统指令，避免先调用原生图片工具再重试。名单外模型保留原有工具、不添加该指令；切换模型后从下一步骤重新判断，子代理按自己的模型独立判断。历史中的旧工具调用记录不会被删除。

调用示例：

```json
{
  "image": "./screenshot.png",
  "prompt": "识别页面里的报错，并逐字抄录错误提示。"
}
```

- `image`：本地 PNG / JPEG / WebP / GIF 路径（相对会话工作目录或绝对路径），也可用当前会话消息中的 `sha256:…` 图片附件 ID；DSH 的文本模型占位符只显示 8 位前缀，无歧义的前缀同样可以解析。
- `prompt`：希望识别的内容，最多 16000 字符。
- 返回 `text`、实际使用的 `provider` / `model`、各次尝试的 `attempts`。
- 不支持图片 URL 或 data URL；避免引入额外下载、SSRF 和凭据边界。
- 只读取当前会话真实图片引用，不按未知附件 ID 探测全局附件存储。图片已被压缩历史移除时，请重新附图或使用本地路径。

## 图片准入放行

DSH 在消息准入层会拒绝「向声明不支持视觉的模型发送图片」（整条消息连同文字一起被拒）。本插件对**白名单中的模型放行这一层检查**：图片得以进入会话，而请求层仍会按 DSH 自身的投影机制把它替换成 `[image omitted …; attachment sha256:xxxxxxxx]` 文本占位符——模型看到占位符和你的问题后调用 `vision_read`，由兜底视觉模型完成识别。图片永远不会被直接发给白名单里的纯文本模型。

- 放行只作用于白名单模型；其他模型保持 DSH 原生拦截。
- 仅放宽「声明为纯文本」的模型（与 dsh-scoped-models 的单向纠错一致）；未声明能力或原生支持视觉的模型不受影响。
- 准入放行只包装公共 `llm.resolveModelInfo`（准入、ACP、子代理共用）；派发路径（`prepareCall`）读取适配器声明值，不受影响。
- 工具选择包装公共 `tools.resolve`，仅在本插件的 `vision_read` 已获当步准入时，从返回的步骤工具集合中移除 `read_image`；声明与原生/PTC 执行共用这一集合，不修改原生工具的全局注册，也不与预设内的同名工具注册冲突。卸载后恢复后续步骤，已准入步骤保持自己的选择。
- 指令通过 `systemPrompt.section` 添加，并以相同步骤工具准入结果为准。第三方预设如果使用完整替换系统提示（`complete`），可能忽略附加指令，但工具屏蔽仍然生效。

## 兜底语义

每次调用固定一份视觉模型列表与超时配置，依次尝试，每项最多一次。抛异常、服务错误、超时、空响应、不完整流或输出截断都会切换到下一项。失败模型的部分结果不会混入最终答案；全部失败时返回模型与错误类别，不泄漏供应商原始异常（可能含请求体或凭据）。

超时涵盖整个模型请求，不是首 token 超时。达到期限会发出取消信号并切换；不遵守取消信号的供应商仍可能在后台处理或计费，其迟到结果会被丢弃。用户取消或插件卸载不会继续兜底。

配置修改从下一次模型步骤起影响工具注入、`read_image` 屏蔽与路由指令；已获准执行的步骤保持自己的工具准入。未匹配的模型不新增此工具，原有工具不受影响。子代理也按各自模型精确匹配。

## 隐私与限制

图片只通过 DSH 既有附件服务接纳、校验与规范化，再通过 DSH 模型连接发送给配置的视觉供应商；不发送整段会话。每个兜底供应商都可能收到图片和问题。文件读取使用部署的 `ctx.fs`，不绕过它直接访问宿主文件系统；读权限遵循该部署文件系统策略。

白名单是工具可用性配置，不是对模型真实视觉能力的自动检测。视觉模型也应确实支持图片输入。识别结果不保证准确；图片中的指令应视为不可信内容。

## 开发验证

设置页由 `client-main.js` 与 `ui-state.js` 组成，`npm run build` 合成浏览器端 `client.js`（提交的产物已生成，`npm run check` 会校验一致性）：

```sh
npm test        # 路由、目录、图片、步骤工具隔离、自动保存状态机与整页渲染交互
npm run check
```

测试涵盖精确匹配、成功与各种错误兜底、整体超时、取消、输出去重、图片格式识别与附件隔离。实际模型端到端调用需在设置中选择用户授权使用的模型后验证。
